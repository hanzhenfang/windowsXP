# 桌面与文件工作流增强设计

## 意图

在现有 Windows XP 风格本地模拟桌面上补齐常用的桌面整理和文件操作，让图标、快捷方式、最近使用、复制/移动/粘贴、搜索、预览和备份恢复形成闭环。继续使用现有 Vue 3、Pinia、Vite 与浏览器本地存储，不连接外部服务。

## 目标与边界

- 桌面图标可按 XP 网格拖放、排列和恢复默认排列；用户自建快捷方式可新增、改名和删除。
- 开始菜单展示最近使用的本地应用。
- 桌面图标位置、快捷方式、最近应用、窗口每应用几何布局在刷新后保留；打开窗口、焦点和 Explorer 选择/剪贴板保持会话状态，不在刷新后自动启动应用。
- Explorer 可在当前目录及其子目录搜索，可多选并复制、剪切、粘贴；文件夹树操作安全地保持层级并拒绝循环移动和冲突覆盖。
- 文件预览明确支持已有本地文本、图片和音频资源，补上基础文件信息及媒体操作。
- 提供版本化本地存档导出和导入，包含文件树、回收站、桌面偏好、系统网络状态和显示/声音偏好。导入先完整验证，再一次性应用；无效存档不改变现有数据。
- 用自动回归覆盖数据服务与关键 UI 交互；改善键盘、焦点、触控和减少动画偏好。

## 非目标

- 不连接网络、不接后端、不实现真实 Windows API、多用户权限、真实网络共享或远端内容下载。
- 不新增动画或音频库。动画继续使用 CSS/Vue，音频继续使用原生 Audio。
- 窗口不会在页面重载后自动打开；剪贴板不是系统剪贴板，也不跨刷新保存。

## 方案与取舍

1. **扩展现有 Pinia/本地 mock 服务（采用）**：遵循项目结构，状态规则可单测，存档内容清楚；需要维护 localStorage schema 与迁移默认值。
2. **把状态直接放进 Vue 组件**：改动初期较少，但复制/移动、导入验证与持久化会分散，难以确保批量操作原子性。
3. **引入完整桌面/文件管理 UI 库**：可快速得到现成交互，但会改变 XP 外观、带入额外依赖，并与现有窗口/文件服务重复。

## 交互约定

- PC 桌面使用可见网格和指针拖动；“排列图标”循环切换名称、类型、手动布局，“自动排列”恢复网格。移动端固定网格顺序，不应用 PC 绝对坐标。
- 创建快捷方式从本地应用清单选目标。系统必备图标仍不可删除；用户快捷方式删除不卸载应用。
- Explorer 搜索在本地文件树中按名称和文本内容过滤。Ctrl/Meta+A、C、X、V 以及 Shift 范围选择按当前 Explorer 选择工作；粘贴目标是当前文件夹。
- 多项操作先验证所有目标和名称再写入一次快照；同名副本依次生成“文件名 - 副本”“文件名 - 副本 (2)”等名称。移动/删除时若同时选择祖先和后代，只执行祖先项的树操作一次。
- 存档版本为 1，使用 JSON 下载与本地文件选择器；拒绝未知版本、缺字段、重复 ID、非法层级或无效偏好。无效导入保留原有本地状态。

## 验收

- 桌面布局和自建快捷方式刷新后保留，最近应用最多保留 5 项；窗口几何在后续打开同一应用时恢复。
- 文件复制包含完整子树且新 ID 唯一；移动拒绝自我/后代循环和名称冲突；多项粘贴不会留下部分写入。
- 搜索可命中文件名和文本内容；剪贴/复制/粘贴、批量删除和回收站还原均能工作。
- 导出存档可导入恢复；无效存档不会修改任何本地数据。
- 自动化回归、类型检查和生产构建通过；手机、平板、桌面视口下交互可用且无横向溢出，减少动态效果设置生效。
- 每个主要模块独立 commit，最终将已验证的提交推到仓库 `master` 以触发 Vercel 生产部署，并核验部署结果。
